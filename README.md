# Language Model Generation Speed Evaluation Datasets

A collection of datasets for benchmarking language-model inference throughput across ordinary text generation,
agentic coding, and tool calling, including speculative decoding and related acceleration methods. 

The prompts in the first dataset consist simply of text strings, whereas the second dataset uses structured prompts
that incorporate the results of tool calls and the LLM’s responses from previous steps in the dialogue.
To simplify working with the first set of prompts, I have separated the datasets into two JSON files.

## First dataset: Multilingual prompts

### Overview

The first dataset contains up to **1,600 prompts across 16 domains**, covering English, Russian, and Chinese. Tasks include mathematics, code generation, grammar correction, question answering, poetry, creative writing, and Russian-to-English translation.

The first dataset’s prompts were selected with the aim of eliciting sufficiently long responses from **Qwen3-0.6B**, so that throughput measurements are less dominated by short generations. Both datasets can be used to compare ordinary autoregressive decoding with acceleration methods such as speculative decoding and lossless drafter-acceptance schemes.

The dataset measures generation performance, not task quality. It does not provide reference answers or define a quality-scoring protocol.

### Files

- [`speed_evaluation_dataset.json`](speed_evaluation_dataset.json) — prompts grouped by domain.
- [`speed_evaluation_dataset.md`](speed_evaluation_dataset.md) — prompt and response length statistics for each domain, measured with the `Qwen/Qwen3-0.6B` tokenizer.
- [`build_speed_evaluation_dataset_v2.py`](build_speed_evaluation_dataset_v2.py) — script used to construct the first dataset.

## Dataset construction

Candidate prompts are deduplicated within each domain and filtered for basic length constraints. The script uses the `Qwen/Qwen3-0.6B` model to
generate greedy responses for candidate prompts, then selects up to 100 prompts per domain by descending generated response length. The
response-length probe allows at most 2,048 new tokens per prompt. Consequently, some recorded response lengths reach this cap; these are
capped measurements, not necessarily the model's natural stopping lengths.

The script uses a fixed shuffle seed for applicable dataset sampling. Reproducing the exact dataset also depends on source-dataset versions,
model and library versions, and access to private or local sources. If a source does not yield enough qualifying candidates, a domain may contain
fewer than 100 prompts.

## Using the dataset

The JSON file maps domain names to lists of prompt strings. The following example downloads the dataset directly from GitHub using only
Python's standard library:

``` python
import json
from urllib.request import urlopen

url = (
    "https://raw.githubusercontent.com/"
    "Koziev/SpeedEvaluationDataset/main/"
    "speed_evaluation_dataset.json"
)

with urlopen(url) as response:
    prompts_by_domain = json.load(response)

for domain, prompts in prompts_by_domain.items():
    print(domain, len(prompts))
    for prompt in prompts:
        # Run the prompt through the model or inference server being evaluated.
        pass
```

    included.

Measure throughput as generated output tokens divided by elapsed wall-clock time, using a consistent token-counting convention across
systems. To compare end-to-end generation speed, include the overheads that occur in the intended deployment path rather than timing only the
model's token-generation kernel. For speculative decoding, also report relevant method-specific settings, such as the drafter configuration and

For the first dataset, prompts were selected using Qwen3-0.6B response lengths, so they are not guaranteed to produce equally long outputs from other models. Some generations may terminate early, and some prompts may hit a generation limit. Interpret aggregate throughput together with per-domain results and output-length statistics.

## Second dataset: agentic coding and tool calling

A second dataset adds **agentic-coding trajectories** and **tool-calling examples**, with 100 samples in each of its two domains by default.
It is intended to benchmark inference on longer conversational contexts and structured assistant tool calls.
The builder produces **100 samples per domain by default** (200 samples total).

### Files

- [`speed_evaluation_dataset_part2.json`](speed_evaluation_dataset_part2.json) — conversation trajectories for agentic coding and tool calling.
- [`speed_evaluation_dataset_part2.md`](speed_evaluation_dataset_part2.md) — per-sample and aggregate token-length statistics for the second dataset.
- [`build_speed_evaluation_dataset_part2.py`](build_speed_evaluation_dataset_part2.py) — script used to construct the second dataset and generate its Markdown statistics report.
- [`smoke_test_speed_evaluation_dataset_part2.py`](smoke_test_speed_evaluation_dataset_part2.py) — smoke test for running examples from the second dataset with Qwen models.

### Domains

| Domain key | Contents | Source |
|---|---|---|
| `agentic_coding` | Multi-message agentic software-engineering trajectories, with an assistant turn selected as the prediction target | [`thoughtworks/agentic-coding-trajectories`](https://huggingface.co/datasets/thoughtworks/agentic-coding-trajectories) |
| `tool_calling` | Function/tool-calling conversations, including declared tool schemas and assistant tool-call targets | [`Archangel-system/glaive-function-calling-v2-openai-native`](https://huggingface.co/datasets/Archangel-system/glaive-function-calling-v2-openai-native) |

### Sampling and structure

- **Agentic coding:** the builder selects valid trajectories across the source dataset's `max_isl` length bands, aiming to retain a range of context sizes. The source `max_isl` values are measured with `cl100k_base`; they are provided as metadata and should not be treated as Qwen-token counts.
- **Tool calling:** the builder filters the source records to those categorized as `tool_call`, then selects examples with a usable assistant tool-call target and tool definitions.
- The output is a JSON **list of sample objects**, unlike the first dataset's JSON object mapping domain names to lists of plain prompt strings.
- Each sample contains a `domain` and a normalized `messages` conversation. Agentic-coding samples store the target turn index in `metadata.target_message_index`; tool-calling samples store it in `validation.target_message_index`. Tool-calling samples also contain `tools` and validation metadata, including expected tool calls and function names.
- The target index marks the assistant message to be predicted. For inference, pass only messages **before** that index as input; do not include the target message in the prompt. For tool-calling examples, include the provided tool definitions when the inference interface supports them.

The accompanying Markdown report records model-specific input and target token lengths using each selected tokenizer's chat template. Input lengths include serialized conversation context and, for tool-calling examples, tool definitions. Expected target lengths include the target assistant turn's serialized representation. These are reference lengths, not model-generated output lengths or measurements of task quality.

### Building the second dataset

The builder requires the Hugging Face `datasets` and `transformers` packages and access to the source datasets and model tokenizers. From the repository directory, run:

```bash
pip install -U datasets transformers
python build_speed_evaluation_dataset_part2.py
```

By default, this writes `speed_evaluation_dataset_part2.json` and `speed_evaluation_dataset_part2.md`, sampling 100 examples per domain. The script accepts `--samples-per-domain`, `--seed`, `--agentic-split`, `--tool-split`, `--stats-models`, and `--output` options; run `python build_speed_evaluation_dataset_part2.py --help` for details. The default statistics tokenizers are `Qwen/Qwen3-0.6B` and `Qwen/Qwen3.5-0.8B`.

## Limitations

-   **Response-length selection bias:** prompts were selected for long greedy responses from Qwen3-0.6B. The dataset is therefore not a
    random sample of typical user traffic.
-   **Model dependence:** prompts that elicit long responses from Qwen3-0.6B may behave differently with other models.
-   **Capped length probes:** response-length measurements stop at 2,048 new tokens, so values at the cap are right-censored by the probe
    limit.
-   **Source and licensing considerations:** prompts originate from multiple datasets and private collections. Users are responsible for
    checking the applicable licenses, terms of use, and redistribution
    requirements for their intended use.
-   **Not a quality benchmark:** these datasets are intended for speed evaluation; they do not by themselves measure correctness, usefulness, or safety.
-   **Different data formats:** the first dataset contains plain prompt strings grouped by domain, while the second contains structured message trajectories, and tool-calling examples include tool schemas and expected tool-call metadata. Benchmark harnesses must handle these formats appropriately.

## Intended use

These datasets are intended for research and engineering comparisons of language-model inference throughput, including evaluations of
speculative decoding and related acceleration techniques. For meaningful comparisons, keep the evaluation protocol consistent and publish the
settings needed to reproduce the measurements.
